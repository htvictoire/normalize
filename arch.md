§3 — Real Losses

- The current app cannot normalize workbook sets or multi-sheet packages as one dataset. Each run is one `SourceRef` and one selected worksheet, so cross-workbook concatenation, schema reconciliation, and provenance columns such as `_source_workbook`, `_source_sheet`, and `_workbook_index` never appear in current outputs. (Plan: `data/implementation_guide_v2.md:1448-1463, 2304-2330, 2390-2404`; Actual: `src/shared/models/source.py:9-15`, `src/shared/models/operation.py:27-34`, `src/suggestion/source/excel.py:40-48`, `src/shared/ingestion/excel/loader.py:43-45`)
- Re-submitting the same source and config does not reuse prior work. `suggest()` creates a fresh UUID-backed instance every time, and persistence is keyed by `id`, not a fingerprint, so identical runs repeat profiling and conversion instead of returning an existing result. (Plan: `data/implementation_guide_v2.md:1205-1208, 1252-1269`; Actual: `src/app/bootstrap/orchestrator.py:44-59`, `src/shared/models/instance.py:48-69`, `src/app/infra/postgres/repository.py:41-61, 119-135`)
- `.xls`, `.ods`, `.xlsb`, `ZIP`, and `TAR` inputs are rejected before processing. The implemented validation surface accepts `.csv`, `.xlsx`, and top-level-array `.json` only. (Plan: `data/implementation_guide_v2.md:1342-1351`; Actual: `src/shared/models/operation.py:13-14, 27-34`, `src/app/bootstrap/validation.py:11-15, 28-63`)
- Runs are evaluated only against their own current contents. There is no persisted baseline or drift report, so the app does not surface “this source added a column,” “this column changed type,” or “quality drifted from the prior accepted shape” as first-class results. (Plan: `data/implementation_guide_v2.md:2357-2385, 1661-1678`; Actual: `src/app/infra/postgres/repository.py:119-135`, `src/shared/models/profiling/output.py:21-29`, `src/shared/models/instance.py:31-46`)
- The pipeline does not emit dedicated anomaly findings for outliers, exact duplicates, fuzzy duplicates, chronology gaps, future/suspicious dates, or cross-column rule violations. Those conditions are not analyzed anywhere in the current path. (Plan: `data/implementation_guide_v2.md:1615-1650, 2529-2557`; Actual: `src/profiling/issues.py:16-57`, `src/conversion/pipeline.py:1-59`, `src/shared/models/normalization.py:20-37`)
- Large and append-only datasets get no architectural shortcut. Normalization always goes through the same single-process conversion path, so there is no partition fan-out for large jobs and no delta-only execution for append-only reruns. (Plan: `data/implementation_guide_v2.md:3022-3117, 3265-3325`; Actual: `src/app/bootstrap/orchestrator.py:92-125`, `src/app/bootstrap/conversion.py:22-56`, `src/conversion/pipeline.py:25-59`, `src/shared/settings.py:10-27`)
- There is no standalone pattern-analysis artifact to hand to downstream consumers. Current artifact output stops at normalized parquet, manifest, and trace. (Plan: `data/implementation_guide_v2.md:2620-2646`; Actual: `src/shared/models/normalization.py:8-18`, `src/conversion/artifacts/stage.py:19-45`, `src/conversion/artifacts/staging.py:37-91`)
- Artifact publication has no application-level completeness gate. S3 uploads go straight to final keys, and the persisted run schema has no `artifacts_complete` field, so the code has no built-in state that distinguishes “all artifacts finalized” from “some files were uploaded.” (Plan: `data/implementation_guide_v2.md:1285-1305, 1833-1837`; Actual: `src/conversion/artifacts/publish.py:51-65`, `src/shared/storage/s3.py:88-93`, `src/app/infra/postgres/repository.py:119-135`)
- The runtime cannot select a version-pinned rule pack or template bundle at execution time. Effective behavior comes from the instance’s confirmed config and the code-defined parsing logic, not from an external bundle identifier plus merge precedence. (Plan: `data/implementation_guide_v2.md:1746-1810`; Actual: `src/shared/models/instance_config.py:10-15`, `src/app/api/models.py:11-20`, `src/shared/settings.py:10-27`)
- The normalize path does not produce terminal warning/block statuses from score evaluation. Once profiling has no `ERROR`, conversion completion stores artifacts and marks the instance `READY`; `READY_WITH_WARNINGS` and `BLOCKED` exist in the enum but are not reached through a decision-evaluation stage in the current normalize flow. (Plan: `data/implementation_guide_v2.md:1223-1248, 1654-1693, 2597-2616`; Actual: `src/app/bootstrap/orchestrator.py:92-125`, `src/conversion/quality_metrics.py:20-91`, `src/shared/models/instance.py:16-28, 89-92`)
- Excel ingestion has no Calamine-style Arrow path. The implemented Excel flow streams rows through `openpyxl` and `executemany()`, so there is no direct Arrow registration path and no workbook-parallel ingest path in the current code. (Plan: `data/implementation_guide_v2.md:1328-1360, 3171-3177`; Actual: `src/shared/ingestion/excel/loader.py:18-79`, `src/suggestion/source/excel.py:60-92`)
